# serbian-app (ucimo) — заметки для Claude

Персональное веб-приложение для изучения сербского с нуля (курс Гриши, бренд
«ucimo»). Go-бэкенд + Vue-фронт в одном бинаре, контент — файлы в `content/`,
состояние (аккаунты, SRS, попытки, прогресс) — PostgreSQL/SQLite. Плюс
отдельный статический лендинг на Nuxt (`landing/`), встроенный в тот же
бинарь и отданный с того же домена.

## Архитектура

- **`server/`** — Go 1.25, stdlib `net/http`. Собирает оба фронта в бинарь
  через `go:embed` (`server/web/dist`, `server/landing/dist`).
  - `internal/content` — грузит и валидирует `content/` (уроки, упражнения,
    словарь, ложные друзья). Hot-reload через fsnotify.
  - `internal/store` — персистентность (аккаунты, identities/сессии, SRS,
    попытки, прогресс).
  - `internal/auth` — примитивы: id/токены, bcrypt-хеши паролей, Telegram
    login-widget/`/start`-подпись, pending-store для `/start`-флоу.
  - `internal/srs` — планировщик повторений (SM-2).
  - `internal/checker` — нормализация и проверка ответов.
  - `internal/mail`, `internal/ratelimit` — почта (верификация/сброс пароля),
    троттлинг логина/регистрации.
  - `internal/api` — JSON API (`/api/...`), см. «Аутентификация» ниже.
  - `main.go` — на `/` сперва пробует статику Nuxt-лендинга (`landing.FS()`,
    напр. `/`, `/privacy`, `/robots.txt`), иначе — Vue SPA
    (`spaHandler(web.FS())`, отдаёт `index.html` для клиентских роутов).
- **`web/`** — Vue 3 + Vite + Pinia + Tailwind. Сам таргетируемый app:
  логин/регистрация, курс, урок (пошаговый плеер), повторение (SRS),
  словарь (табы «Слова»/«Ловушки», один экран — `VocabView.vue`),
  профиль/рейтинг.
- **`landing/`** — Nuxt 4, отдельный `package.json`/`npm run build`, чисто
  статический маркетинговый сайт (SEO/GEO, аналитика, `/privacy`, `/terms`).
  Не трогает `/api` и не завязан на аутентификацию.
- **`content/`** — единственный источник правды по учебному материалу
  (см. `README.md` → «Контент»). Уроки — манифесты `lessons/NN.yaml`
  (шаги) + фрагменты `lessons/NN/*.md`; легаси `lessons/NN-*.md` +
  `exercises/NN.yaml` ещё поддерживается. Плюс `vocab.yaml`,
  `allow-words.yaml`, `persona.yaml`, `false-friends.yaml`, `images/`,
  `audio/`.

## Аутентификация

Сессионная, не по имени: email+пароль, и/или вход через Telegram-бота
(`/start`-диплинк — открывает бота, тот дёргает вебхук, фронт поллит
`/api/auth/telegram/poll`). Email требует подтверждения (иначе роут-гвард
фронта загоняет на `/verify`); Telegram-only аккаунт email не имеет и
подтверждения не требует. Сессия — httpOnly-кука, `internal/store` хранит
её хешированный токен; пароль — bcrypt.

- Публичные (без сессии): `POST /api/auth/{register,login,logout}`,
  `GET /api/auth/verify`, `POST /api/auth/{resend-verification,forgot,reset}`,
  `POST /api/auth/telegram(/start)`, `GET /api/auth/telegram/poll`,
  `POST /api/telegram/webhook` (аутентифицирован отдельным секретом от
  Telegram, не сессией).
- `requireSession` (строго кука, без легаси-моста) — всё account-scoped:
  `/api/me*`, `/api/auth/{logout-all,session}`.
- `requireAuth` (кука ИЛИ легаси `X-User`-заголовок) — весь остальной
  `/api/*`: курс, уроки, упражнения, SRS-очередь, словарь, лидерборд.
  `X-User` жив только для переходного периода — не должен доходить ни до
  чего account-scoped.
- Троттлинг — `internal/ratelimit` (по IP и по email/ключу), плюс
  soft-lock после N неудачных попыток.

## База данных — PostgreSQL (прод) / SQLite (локально)

**Один код, два бэкенда.** `store.Open(dsn)`:

- `dsn` начинается с `postgres://` / `postgresql://` → **PostgreSQL** (драйвер
  `pgx/v5/stdlib`).
- иначе → **SQLite** (`modernc.org/sqlite`, чистый Go), `dsn` = путь к файлу
  или `:memory:`.

Запросы пишутся с плейсхолдерами `?`; для Postgres они переписываются в `$N`
функцией `rebind` в `store.go`. Схема — `schemaSQL(pg bool)`, отличие только в
колонке автоинкремента. Idempotent `CREATE TABLE IF NOT EXISTS`, миграций
руками нет (кроме `internal/store/migrations` — версионированные шаги схемы,
`migrate.go`).

### Прод (Dokploy)

Отдельный сервис **PostgreSQL** в проекте, приложение получает
`DATABASE_URL` через env. Редеплой приложения базу не трогает. Полностью —
`docs/DEPLOY.md`. Деплоится через Dokploy API (`git push` сам по себе не
триггерит редеплой — см. память «Serbian app deploy access»).

### Локально

По умолчанию SQLite-файл `./data/app.db` — ничего ставить не нужно.
`make dev` поднимает фронт (5173) и бэк (8080). Локальный тестовый аккаунт
можно создать через `/register` и вручную проставить
`identities.email_verified_at` в SQLite, чтобы обойти письмо с
подтверждением.

### Тесты

- `make test` / `go test ./server/...` — стор гоняется на SQLite in-memory.
- Против настоящего Postgres: `TEST_DATABASE_URL='postgres://localhost/srpski_test?sslmode=disable' go test ./server/internal/store/`
  (таблицы `TRUNCATE` между тестами). `make test-pg` — то же.
- Локальный тест-Postgres: `createdb srpski_test` (нужен запущенный
  `postgresql@17` из brew) или свой docker.
- Фронт: `cd web && npx vitest run` (юнит/компонентные), `npx vue-tsc -b` (типы).

## Модель урока: манифест + шаги

У урока две модели, `content/load.go` выбирает по расширению `file:` в
`course.yaml`:

- **манифест** (`file: "lessons/NN.yaml"`) — новая, единственная в реальном
  контенте сейчас. Урок = упорядоченный список **шагов**:
  `teach` (теория), `practice` (упражнения), `reading` (текст + опц.
  упражнения), `dialogue` (пошаговый диалог, см. ниже), `checkpoint`
  (упражнения-проверка). Теория — фрагменты `content/lessons/NN/*.md`,
  упражнения — инлайн в шаге. Пример со всеми видами —
  `content/lessons/_TEMPLATE.yaml`.
- **легаси** (`file: "lessons/NN-slug.md"` + `content/exercises/NN.yaml`)
  — загрузчик синтезирует из неё шаги (teach → practice-блоки → reading).
  В реальном `content/` легаси-уроков не осталось; синтез шагов покрыт
  тестом на фикстуре (`testdata/content`).

Прогресс — по шагам (`store.lesson_step_progress`), экран урока —
пошаговый плеер (`web/src/views/LessonView.vue`, мобайл-first): один
экран = один шаг, либо (для `practice`/`reading`/`checkpoint` с
несколькими упражнениями) одно упражнение за раз, листается «Дальше».
Кнопка «Назад» в заголовке листает назад в том же гранулярном порядке —
внутри диалогового шага она отменяет последний ответ **этой сессии**
(шаг за шагом), а не сразу выходит из шага (см. `DialogueStep.vue`
`stepBack()` + `LessonView.vue` `goBack()`).

### Диалоговый шаг (`kind: dialogue`)

Реплики (`turns:`) чередуют `npc`/`me`; каждая `me`-реплика несёт
`exercise:` (только `choice`/`translate`/`fill_blank`). Разговор
раскрывается сверху вниз по мере ответов (`DialogueStep.vue`), без
постраничной навигации — весь шаг живёт на одном экране. У шага общий
`step.Exercises` (как и у practice/checkpoint, `collectExercises` в
`manifest.go`), поэтому назад-навигация и «один Проверить видим
одновременно» логика в `LessonView.vue` учитывают dialogue отдельно
(`activeDialogueExercise`), а не через обычный `paginatesExercises`.

**`fill_blank` в диалоге:** `sr`/`ru` самой реплики скрыты до ответа
(см. `Turn.SR`/`Turn.RU`), так что `prompt` — единственная подсказка.
Голый сербский промпт без русского ориентира (`"Malo. ___ srpski."`)
угадывается неоднозначно, если на пропущенное место грамматически
подходит больше одного слова (было: `02.10.3`, `05.18.2`, `09.16.3`,
исправлено русской подсказкой `«...» → ...` по образцу остальных
`fill_blank`). Без русской подсказки оставляй только когда ответ
вынужден грамматикой (`06.8.6`: время только с `u`) или дословно
повторяет слово из видимой предыдущей реплики (`10.18.2`: эхо
услышанного). Иначе — либо добавляй `«русский» → сербский с ___`, либо
меняй на `choice` с русским `prompt`, как у соседних реплик того же
диалога.

## Короткие уроки и уровни

**Как делать такие уроки, шаг за шагом: `docs/LESSON_AUTHORING.md`** (формат, спеки для `scripts/gen_lesson.py`, образцы в
`scripts/lesson_specs/level2/`, ловушки сербского, проверки, награды и цены, как переделать старые уроки 16–77).
Читай его перед тем, как писать или править урок.

Уровни 1 и 2 нарезаны на короткие уроки (17 и 23; спека: `docs/superpowers/specs/2026-10-20-level1-rework-design.md`).
Формат урока: **вводный** (слайд с одной-двумя фразами → сразу микрозадание на них → общая лесенка заданий:
«послушай и выбери» → соедини → собери → напиши) и **повторение** после двух вводных (без теории, 10–14 заданий,
диктант и перевод, мини-диалог там, где слова складываются в разговор). Размер вводного зависит от темы: 3–4
фразы у трудного, 7–10 у темы с понятным принципом. Заготовка: `scripts/gen_lesson.py` (спека → манифест + слайды).

- **Id уроков.** Первый кусок старого урока хранит номер (`02`), следующие получают суффикс (`02b`, `02c`…).
  Строковый порядок id должен совпадать с порядком курса: `orderedVocab` сортирует `vocab.lesson` как строку.
  У переиспользованного id шаги и задания нумеруются с 11 (`02.11`, `02.12.1`), чтобы не пересечься с
  идентификаторами старого урока (по ним лежат попытки учеников).
- **Слово привязано к уроку, где его вводят** (`vocab.lesson`, `teaches`); в заданиях урока разрешены только слова
  из накопительного словаря (`lexicon_test.go`), а услышанная фраза («послушай и выбери», диктант) должна
  встречаться в тексте раньше (`seen_in_text_test.go`).
- **Незнакомые формы остаются готовыми фразами** (`Imam sina`, `Nemam sestre`, `godina/godine`, `dugujem`): в вводном
  уроке только на узнавание (выбор, соедини, фишки), без `fill_blank`/`translate`, где форму нужно менять самому;
  в повторении готовую фразу можно переводить целиком. Падежи — уровень 5. После `nemam` нужен родительный:
  `Nemam sestre`, `Nemam dece` (не `Nemam sestru`).
- **Уровни и деньги.** Карта курса — `phases` в `course.yaml`: `1`, `1b` (Уровень 2 — Числа и магазин), `2`…`5`.
  Бесплатен только уровень 1. Остальные закрыты товарами `phase_unlock` (ref = id фазы) и стоят 40 / 150 / 260 / 370 / 480
  зёрнышек (`SeedEconomyDefaults`, миграция 030 для уже посеянной базы). Второй уровень открывается одними уроками
  первого с запасом (его награда 52, цена не больше четырёх пятых), третий набирается уроками и обычными квестами, четвёртый
  копится с серией, пятый и шестой покупают. Цены привязаны к «эталонному ученику» (урок в день, серия без пропусков,
  подписан на канал, друзей не звал): накопленная цена уровня 3 не выше того, что дают уроки и обычные квесты без
  серии, уровня 4 выше этого и не выше полного дохода ученика, уровней 5–6 выше дохода. Цены не убывают от уровня к
  уровню (иначе поздний можно купить раньше раннего). Арифметику держит `TestSeededEconomyMatchesTheDesign`; меняешь
  награду или цену, меняй и расчёт в комментарии к `SeedEconomyDefaults` и в
  `docs/superpowers/specs/2026-09-28-currency-design.md`.
  Внутренние id фаз не меняются при переименовании уровней: меняются только названия («Уровень 5 — …»).
- **Награды.** Платят все уроки, и короткие (`02b`) наравне с длинными: 2, а каждый четвёртый 4, плюс бонус за
  завершение уровня; итоги уровней 52 / 70 / 70 / 90 / 110 (`lessonPay`, `defaultQuests`). Награды сеются один раз;
  уже посеянную базу меняет только миграция (условные UPDATE «если значение ещё старое посеянное», чтобы правки из
  админки пережили).
- **Проверка, что никто не потерял начатое:** `scripts/check_kept_levels.sql` (только чтение, на прод-базе должен вернуть 0 строк: кто начинал
  платный уровень, но не имеет его открытым). «Начал» это любая строка в `lesson_progress`, `lesson_step_progress` или `attempts` по
  урокам уровня. Старые уровни 4 и 5 это нынешние 5 и 6 с теми же id фаз и теми же уроками, поэтому купленное осталось купленным.
  `scripts/check_kept_purchases.sql` проверяет то же для купленного (за зёрнышки, по промокоду, за рубли, годовой доступ): ищет
  «получено, а права нет», на проде тоже должен вернуть 0 строк.
- **Не отнимать начатое.** Миграция 030 выдаёт открытие фазы тем, у кого уже есть прогресс в уровне, который раньше был
  бесплатным (`lesson_progress`). Новая платная фаза без такой строки заперла бы действующих учеников посреди курса.

## Добавить урок (манифест)

1. `content/course.yaml` — запись урока с `file: "lessons/NN.yaml"`.
2. `content/lessons/NN.yaml` — манифест (скопируй `_TEMPLATE.yaml`).
3. `content/lessons/NN/*.md` — фрагменты теории для `teach`/`reading`;
   каждое новое сербское слово/фразу в `teach`-шаге сразу снабжай
   транскрипцией (см. «Русская транскрипция слов» ниже) — не отдельным
   проходом потом.
4. Новые слова → `content/vocab.yaml` (`lesson: "NN"`) **с полем
   `transcription:`**, продублируй их id в `teaches:` манифеста.
5. Падежные формы, имена → `also_ok:` конкретного шага; общие
   имена/числа/частицы → `content/allow-words.yaml`.
6. `python3 scripts/tts.py` — озвучка новых слов и `listen`-упражнений/
   диалоговых реплик.
7. `python3 scripts/check_transcriptions.py` — гард на транскрипции
   (см. ниже); должен выйти с `OK`.
8. `make lint-sr` — орфография, экавица, алфавиты, диакритика, кириллица
   словаря и сверка ударений со словарём (см. «Проверка сербского»).
   Находок быть не должно; в отчёте по ударениям не должно появиться
   НОВЫХ слов.
   Тот же `make lint-sr` гоняет `check_cyrillic.py`: новое слово с `nj/lj/dž` на стыке
   морфем и текст, который ломается в кириллице, он покажет сам.

**Гард-тесты** (`server/internal/content/`):
- `real_test.go` — структура уроков, наличие reading/checkpoint, аудио
  для `listen`.
- `lexicon_test.go` — в манифест-уроке `accept` / `options` / `bank` /
  сербская сторона `pairs` / `say` используют только слова из
  накопительного словаря к этому уроку (+ `teaches` / `also_ok` /
  `allow-words`).
- `seen_in_text_test.go` — строже предыдущего: слова диктанта (`listen`) и
  ячейки таблицы спряжения (`conjugate`, включая подписи `mi/vi/oni…`) должны
  встречаться в ТЕКСТЕ теории/чтения/диалогов раньше (поле `lesson` в
  vocab.yaml и `teaches` доказательством не считаются — на них слово
  «числилось», хотя ученик его в уроке не видел). Для остальных заданий —
  отчёт `python3 scripts/audit_unseen_words.py --strict --new-only`.
  Тот же файл держит русскую сторону диктанта (`TestDictationRussianAnswerSeenInText`): у `listen` в «Не могу прослушать»
  и в «Повторить» ученик видит `ru[0]` как «Правильно», поэтому каждое его слово должно быть в русском тексте теории, перевода
  чтения или диалога раньше (числительные освобождены, их учат цифрами). Первым в `ru` ставь перевод, которому учил урок
  (случай 2026-10-31: «Hvala, prijatno!» → «приятного аппетита», когда `prijatno` учили как «всего доброго»); прочие варианты
  только принимаются и свободны. Новый смысл слова сначала вводи в теории урока, потом используй в заданиях.
- порядок сложности в `practice`-шаге не убывает (иначе `mixed: true`);
  у `dialogue` порядок — сценарный, не проверяется.

### Русская транскрипция слов

Каждое слово в `vocab.yaml` несёт `transcription:` (русская кириллица
с ударением) — показывается в «Словарь → Слова» и в карточке по клику
на слово (`GlossedText.vue`/`/api/lookup`). В `teach`-шагах теории то
же самое инлайн в тексте:

```
- `molim` [мо́лим] *(молим — пожалуйста)* — «пожалуйста». А ещё...
```

Серьёзное слово/фраза — в `` `бэктиках` `` (даёт подсвеченную плашку,
как в `04/1-jesam.md`), сразу после — `[транскрипция]`, дальше без
изменений старый формат `*(кириллица — перевод)*`. **Не** трогай
`reading`/`dialogue`/`listen`/`checkpoint` — транскрипция только в
`teach`-прозе и в `vocab.yaml` (в диктанте и проверке она была бы
спойлером; текст для чтения и так кликабелен через словарь).

**Транслитерация** (движок и таблица разом — `scripts/translit_ru.py`).
Источники правил — две страницы, на которые мы опираемся, если нужно что-то
менять: [srpski.ru — как читать по-сербски](https://www.srpski.ru/2026/09/kak-chitat-po-serbski/)
и [respect.rs — грамматика, азбука с русской транскрипцией](https://www.respect.rs/facts/grammar).
Запись — подсказка для русского глаза, а не точная фонетика.

| Латиница | Русская запись | Заметка |
|---|---|---|
| `e` | **`э`** всегда: `ne`→`нэ`, `levo`→`лэ́во`, `može`→`мо́жэ`, `centar`→`цэ́нтар`, `jedanaest`→`едана́эст` | сербское `e` **не смягчает** согласную — главная ловушка русского чтения |
| `je` | `е`: `je`→`е`, `moje`→`мо́е` | единственное «е» (плюс `lje`/`nje`) |
| `j` + гласная | `я`/`е`/`ю`/`ё` (`ja`→`я`, `jutro`→`ю́тро`); `ji`→**`йи`** (`koji`→`ко́йи`) | `ји` йотированной буквой не записать, иначе `koji` читалось бы «кои» |
| `j` иначе | `й` | |
| `lj`, `nj` | `ль`/`нь`; перед гласной `ля/лю/ле/лё`, `ня/ню/не/нё` | `bolje`→`бо́ле`, `njega`→`не́га` |
| `č` | `ч` | тверже русского «ч» |
| `ć` | `ч` | мягче `č`; в записи оба «ч» — разницу слышат, а не пишут |
| `đ` | **`дьжь`** (`дьж` перед гласной): `doviđenja`→`дови́дьжэня`, `Đorđe`→`дьжо́рдьжэ` | мягкий слитный звук |
| `dž` | `дж`: `džem`→`джэм` | твёрдое; **не** то же, что `đ` |
| `š`, `ž`, `c`, `h` | `ш`, `ж`, `ц`, `х` | |

**Ударение** — один акут (´, U+0301) на ударной гласной. Никогда не
ставь его: (а) на последнем слоге слова — в сербском там ударения не
бывает никогда (обе страницы-источника это подтверждают; исключения —
отдельные слова иностранного происхождения; в нашей записи таких нет); (б) в
односложных словах; (в) на клитиках внутри фразы (`je`, `se`, `mi`,
`ti`, `da`, `li`, `su`, `ću/ćeš/će/ćemo/ćete` и т.п. — в потоке речи они
безударны, даже если не уверен в основном слове).

Слоговое `r` (между согласными: `srpski`, `brzo`, `grlo`, `Srbija`) тоже
ударный слог: акут ставится на само `р` — `ср́пски`, `бр́зо`, `гр́ло`,
`Ср́бия`. В двусложном слове со слоговым `r` в первом слоге место
ударения выводится из правила (раз не на последнем — значит на `р`);
для длиннее — только по словарю.

Ориентир, **не правило**: ударение чаще падает на первые слоги, а в
словах, похожих на русские, — на слог раньше (русское `рука́` — сербское
`ру́ка`, `нога́` — `но́га`). В сербском четыре типа ударения (долгота и
тон), на письме и в нашей записи они не отражаются.

Пример вызова движка, когда транскрипцию нельзя просто скопировать из
`vocab.yaml` (словоформа/фраза): `python3 scripts/translit_ru.py "kako
da dođem" 1 0 1` → указываешь номер ударной гласной для каждого слова
по порядку (0 — без ударения, для клитик; слоговое `r` считается
ударным слогом, как и гласная).

**После правки — обязательно:**
```bash
python3 scripts/translit_ru.py --self-test   # если трогал движок
python3 scripts/check_transcriptions.py
```
Проверка ловит: ударение на последнем слоге и несколько ударений в
слове, сербские буквы (ј/њ/љ/ђ/ћ/џ) в русской записи, несовпадение
транскрипции одного и того же слова в разных местах курса, ударение на
клитике, несбалансированные `` ` ``/`[]`/`()` — и главное,
**любое расхождение с движком**: каждая транскрипция (в `vocab.yaml`,
`false-friends.yaml` и `[…]` после `` `латиницы` `` в уроках) должна
совпасть с тем, что даёт `translit_ru.py` для её сербского источника с
тем же ударением. Поэтому буквенные правила (`e`→`э`, `đ`, `ji`)
нельзя нарушить по невнимательности — ни в новом слове, ни в старом.
Не ловит и не может ловить: собственно правильность места ударения —
сербская акцентуация не выводится из правил, только из словаря/носителя.
Для лемм из `vocab.yaml` словарная сверка есть — `scripts/check_stress.py` (см.
«Проверка сербского»); ударения словоформ и фраз не проверяет ничто.
Ориентируйся на реальные примеры в `vocab.yaml` (`molim`→`мо́лим`,
`izvinite`→`изви́нитэ`, `engleski`→`э́нглэски`, `dinar`→`ди́нар`,
`doviđenja`→`дови́дьжэня`) — и, если сомневаешься сильно, лучше спросить
у Гриши, чем гадать.

### Проверка сербского (ошибки, линтер, ударения)

Сербский пишет модель, не носитель — поэтому ошибки ловим не «аккуратностью», а
источником правды и проверками. Полный регистр классов ошибок, что ловится
машиной и что только глазами — `docs/SERBIAN_ERRORS.md`. Коротко:

- **Глагол называем по инфинитиву, не по форме.** «Быть» — `biti` (как «быть или не быть»:
  `Biti ili ne biti.`), а не `jesam`: это лишь 1-е лицо ед. ч. полной формы (по Викисловарю
  «first-person singular present of bȉti»), а в таблице урока стоят короткие `sam/si/je`.
  Так же `raditi`, `imati`: в заголовках уроков, шагов, карточек и плашках заданий (`meta`)
  только инфинитив. Полные формы `jesam/jesi/…` — отдельно, для вопросов и коротких ответов.
  Ученица запутывалась именно на «глагол быть — jesam» (2026-10-22).
- `make lint-sr` (нужно `pip3 install spylls pyyaml`; словарь качается сам в
  `scripts/.cache/`). `scripts/lint_serbian.py` проверяет только то, что обязано
  быть верным (`answer`/`accept`/`say`, реплики, код-спаны теории, чтение,
  словарь; намеренно неверные `options` и `fix_error.prompt` не трогает):
  SPELL — нет в словаре; YAT — иекавизм/хорватизм; DIAC — слово без диакритики,
  у которого «двойник» с ć/č/š/ž/đ тоже слово (`skoli`↔`školi`); CYR — кириллица
  словаря ≠ транслит `latin`; SCRIPT — смешение алфавитов в слове.
- Исключения — `content/lint-serbian.yaml` (`allow`, `allow_in`, `yat_ok`,
  `diac_ok`, чёрный список `croatisms`); **причина у каждой записи обязательна**.
  Верное слово, которого нет в словаре, — в `allow`; намеренно неверное
  написание в конкретном уроке — в `allow_in`, а не глобально.
- Ударения: `python3 scripts/check_stress.py` сверяет ударный слог лемм
  `vocab.yaml` с Wiktionary и пишет очередь `docs/stress-queue.md`
  (`--write-queue`). Это **очередь на проверку, а не приговор**: Wiktionary
  следует прежде всего хорватской норме. Уровень A (нисходящее ударение в
  Wiktionary) — вероятная ошибка курса; уровень B (восходящее) — нужен носитель.
  Подтверждённое «курс прав» — в `content/stress-decisions.yaml` с `source`.
- `python3 scripts/check_stress_tokens.py` (входит в `make lint-sr`) сверяет с Wiktionary
  КАЖДОЕ слово из русских транскрипций, не только леммы словаря. Уровень A
  (нисходящее ударение, надёжно для обеих норм) — ошибка курса, код возврата 1;
  уровень B (восходящее) — отчёт для носителя, `--all` покажет список. Исключение —
  `keep_words:` в `content/stress-decisions.yaml` с `source`.
  `--write-queue` пишет `docs/stress-queue-tokens.md`: слова уровня B и слова, где курс
  повторяет Wiktionary с восходящим ударением не на первом слоге (очередь для носителя).
- `python3 scripts/check_cyrillic.py` (входит в `make lint-sr`) проверяет, что показ курса
  кириллицей безопасен (см. «Письмо: латиница / кириллица» ниже): сверяет конвертер с
  общими примерами и с авторской `cyrillic` всех слов, ищет римские цифры латиницей в
  русском тексте, разговоры о самих письмах, латинские слова с q/w/x/y и слова, где
  `nj/lj/dž` могут быть двумя буквами. Просмотренные слова — в `content/cyrillic.yaml`
  (`digraph_ok`, причина обязательна).
  `make lint-cyr` (то же с `--dictionary`, ~30 с) — независимая половина: каждое слово
  курса после конвертации должно быть в настоящем кириллическом словаре LibreOffice
  (`sr`; скачивается в `scripts/.cache/`), если латинское есть в `sr-Latn`. Исключения —
  `dictionary_ok` в `content/cyrillic.yaml`. Именно он нашёл «Prošlost II» → «ИИ»:
  римские цифры в названиях пишутся символами Ⅱ Ⅲ Ⅳ.
- Новое слово: ударение берём из Wiktionary/словаря, а не «на глаз». Нет данных
  или источники спорят — слово в очередь, а не в курс «как показалось». Среди
  найденных расхождений преобладает ударение на слог позже, чем в словаре —
  не ставь ударение на второй слог по умолчанию.
- Словарная сверка (сеть, источник правды — словари): `python3 scripts/check_translations.py --lesson <id>` (перевод слов по
  ru.wiktionary и en.wiktionary; `--sentences` — фразы против Tatoeba) и `python3 scripts/check_grammar.py --lesson <id> --fetch`
  (падежи, числа, род, лицо по таблицам склонения Wiktionary; `--self-test` проверяет сам скрипт). Подробности и ограничения —
  `docs/LESSON_AUTHORING.md`, п. 8; чего избегать по данным прода — п. 14.
- Проверяешь гард — убедись, что он ловит: внеси ошибку в копию `content/` и
  запусти `python3 scripts/lint_serbian.py --content <копия>`. «0 находок» без
  этого ничего не доказывает.
- Нашёл новую ошибку — не только исправь, а пройди «Процесс» из
  `docs/SERBIAN_ERRORS.md` (класс → правило/гард → пример).

### Текст для чтения

Манифест: шаг `kind: reading`, `md:` на фрагмент, где строка `---`
делит сербский текст и русский перевод. Попадает в `Step.Markdown` /
`Step.MarkdownRU`.

Клик по слову → карточка из словаря — общий компонент `GlossedText.vue`
(токенайзер `lib/reading.ts`, общий кэш `lib/lookup.ts`, эндпоинт
`/api/lookup?q=`). Используется в тексте для чтения, в промптах упражнений
`fill_blank` / `fix_error` и в репликах диалога. Промпты `translate`
(русские, ответ спойлить нельзя) — без глоссов. В карточке слова —
кнопка «＋ в повторение» (`POST /api/review/add {vocab_id}`).

### Типы упражнений

`translate`, `fill_blank`, `fix_error`, `conjugate`, `listen`
(диктант — `say:` синтезируется, `accept:` печатают; обязательный `ru:` —
допустимые русские переводы `say`, см. ниже), плюс лёгкие:
`choice` (`options` + `answer`), `word_bank` (`bank` из фишек +
`accept`), `match` (`pairs` [sr, ru]). Клиенту НИКОГДА не уходят
`accept` / `answer` / соответствие `pairs` / `say` — только
`options` / `bank` / `left` / `right`, перемешиваются на клиенте.
Проверка — `POST /api/lessons/{id}/exercises/{exId}/check`. Заданий «напиши
своё и оцени себя» (`free`) больше нет — загрузчик на них падает.

**Подсказки и мягкая проверка** (по данным прода: узнавание решается на 90–98%,
набор текста — на 23–55%, см. `docs/SERBIAN_ERRORS.md`):
- `hint:` у упражнения — подсказка 💡 **до** ответа (кнопка `HintButton`), после
  проверки не повторяется. Это подталкивание (правило, первая буква, где искать),
  а не ответ: загрузчик (`content/hint.go`, `validateHint`) падает, если в подсказке
  целиком есть любой допустимый ответ. `explain:` — наоборот, объяснение после
  ответа (но показывается и до него, если нет `hint`, поэтому в нём тоже нельзя
  писать ответ). Ставь `hint` на задания, где первая попытка < ~55%.
- Проверка ответа (`checker.Check`, `checker/tolerance.go`) прощает, но **помечает**
  («Засчитано, но проверь написание: …»): сербскую кириллицу (`коњ`); потерянную или
  перепутанную диакритику (`c/č/ć`, `s/š`, `z/ž`, `dj/đ`) в любом месте слова; **любую
  разницу в одну букву** (подмена, пропуск, лишняя, перестановка двух соседних) в одном слове
  ответа, если слово в ожидаемом ответе не короче **4 букв**, и в окончании тоже: ученику главное
  знать слово, а не писать его без ошибок (решение владельца курса 2026-10-23). Слова из 1–3 букв
  (`si`/`su`/`je`/`ja`) остаются точными. Страховка: попытка пишется с `typo = 1`, и «Повторить»
  возвращает такое задание, пока ответ не написан точно (`sin` вместо `sina` не пройдёт мимо
  навсегда). Строгое правило (`checker.CheckStrict`: защищены последние 2 буквы, 3 для слов от 7 букв;
  диакритика и удвоенная буква по-прежнему прощаются) остаётся там, где одна буква и есть смысл:
  таблицы спряжения (`CheckForms`; иначе `imaš`/`imam` засчитывались бы друг за друга), `fix_error`
  (поле заранее заполнено неверным предложением: `Imam brat.` не должно пройти за опечатку `Imam brata.`;
  сданное без изменений предложение не засчитывается никогда, даже когда исправление только в диакритике)
  и `word_bank` (фишки выбирают, а не печатают: `sin` вместо `sina` это неверный выбор). Это держат
  `TestRealCourseFixErrorDoesNotPassUnchanged` и `TestRealCourseWordBankLookalikeTilesStayWrong`, которые
  прогоняют все такие задания курса. Менять правило — только вместе с `tolerance_test.go`.
- **Что писать: слово или предложение.** Сервер кладёт в задание поле `shape` (`answerShape` в `api/api.go`, по
  допустимым ответам, сам ответ не уходит): `word` (все варианты из одного слова), `phrase`, `blank`
  (`fill_blank`), `sentence` (`fix_error`). У каждого текстового задания рядом с условием стоит «?»
  (`HintButton`): сначала строка про то, что писать, потом подсказка задания, если она есть
  (`TextAnswer.vue`, `formatLine`). Если ответ — лишь часть правильного (одно исправленное слово вместо
  предложения, первые слова фразы; `checker.TooShort`, только `translate`/`fix_error`/`listen`), `check`
  отвечает `{"format":"too_short"}`: ничего не оценивается и **не записывается** (попытки нет, красного нет),
  в поле остаётся набранное, под ним жёлтая строка «Это только часть ответа…», и ученик дописывает без штрафа.
  Ответ не раскрывается.
- `fill_blank`: допустим и пропущенное слово, и целая фраза с ним
  (`content.FillSentences` — синхронно с `fill_sentence` в `tts.py`). `fix_error`:
  поле ввода заранее заполнено неверным предложением (его правят, а не переписывают),
  если в промпте нет русского текста.

**«Послушай и выбери»** — `choice` с полем `say`: играет клип (`<id>.mp3`), текст скрыт, варианты русские
(смысл фразы; загрузчик требует русский `answer`). В режиме «не могу прослушать» вместо клипа показывается сама
фраза (`text`), после ответа фраза раскрывается (`say` в результате проверки). Озвучка — `tts.py`.

«Не могу прослушать»: нажатие превращает все диктанты урока в «переведи
предложение на русский» до завершения урока (флаг `lesson.silent.<id>` в
localStorage). `GET .../exercises?audio=off` отдаёт `say` как `text`
(только в этом режиме), а `check` с `{ru: true}` сверяет ответ с `ru:`.
Компоненты —
`web/src/components/exercises/*Answer.vue`; `translate`/`fill_blank`/
`fix_error`/`listen` делят `TextAnswer.vue`.

Каждый Answer-компонент, у которого своя кнопка «Проверить», рисует её
через общий `BottomBar.vue` (закреплён снизу) — `LessonView.vue`
(`showOwnBottomButton`) следит, чтобы одновременно был виден только один
нижний бар (свой или общий «Дальше»).

### Письмо: латиница / кириллица

Курс написан латиницей; учащийся может читать его кириллицей. Подробно —
`docs/superpowers/specs/2026-10-19-cyrillic-switch-design.md`. Правило одно:
**конвертируем только в момент показа, в компоненте, который рисует строку.**
Значения, id, ключи озвучки и всё, что уходит на сервер, остаются латиницей:
`choice`/`word_bank`/`match` отправляют текст варианта, и сервер сравнивает его с
латинским ответом; клип озвучки ищется по хешу латинского текста; слово по тапу
ищется в словаре по латинскому написанию. Ввод кириллицей проверка ответов
принимала и раньше (`checker.SerbianCyrillicToLatin`).

- Настройка — `users.script` (`latin` по умолчанию, миграция 029), поле `script` в
  аккаунте, `PATCH /api/me {script}`. Переключатель — `ScriptToggle.vue` (полный вид в
  профиле → Настройки, компактный «Лат | Кир» в шапках урока, повторения, словаря и
  «Работы над ошибками»); `session.setScript` меняет сразу, при отказе сервера
  возвращает старое.
- Конвертер — `web/src/lib/script.ts` (`toCyrillic`, чистая функция), хук
  `lib/useScript.ts` (`show(text)`, `script`). Компонент рисует `show(x)`, а не `x`.
  Конвертируются только латинские отрезки: в курсе сербский всегда латиницей, русский
  кириллицей, поэтому языковые пометки не нужны. Копия на Python — в
  `scripts/check_cyrillic.py`; обе держатся в согласии общими примерами
  `web/src/lib/translit_vectors.json` (как `phraseKey` ⇄ `tts.py`). Файл лежит внутри `web/`
  намеренно: Docker собирает фронтенд, видя только `web/`, импорт из-за её пределов ломает сборку.
- **Ловушка с ударением.** Ударение — комбинирующий акут U+0301 после гласной, а «ć» в
  разложенном виде — это `c` + тот же U+0301. Поэтому слепой Unicode-нормализации нет:
  конвертер раскладывает, собирает обратно `c`+акут → `ć`, `c/s/z`+гачек → `č š ž` и
  только потом переводит. Русский текст не трогается (иначе развалились бы й и ё).
- Сам тогл (`ScriptToggle.vue`): две равные половины и одна подсветка (`script-thumb`),
  которая переезжает под активную кнопку (`transform`, 0,2 с; `motion-reduce` отключает),
  кнопки несут только подписи. В шаблоне над корневым элементом нельзя оставлять комментарий:
  у компонента станет два корня, и классы от родителя (`ml-auto` в шапках) перестанут
  применяться.
- Переключение письма внутри урока сопровождается мягким проявлением нового текста
  (`lib/flipText.ts`, WAAPI). Только `opacity`: `transform` или `filter` на обёртке урока
  на время анимации сделали бы её контейнером для закреплённой снизу кнопки «Проверить», и
  кнопка прыгнула бы. Уважает `prefers-reduced-motion`; текст при этом не пересоздаётся, так
  что набранный ответ не теряется.
- Урок про сами буквы остаётся латиницей: `script: latin` в манифесте (сейчас 00, 01 и
  56 — «стриженая» латиница), в ответе урока это `keep_latin`, внутри такого урока
  `provideKeepLatin` велит всем `useScript()` показывать латиницу, а переключатель в
  шапке прячется с пояснением.
- Римские цифры в русском тексте писать символами Ⅰ Ⅱ Ⅲ Ⅳ (не латиницей), английские
  слова в русском тексте — не оставлять: конвертер сделает из них «литерари».
  `check_cyrillic.py` на такое ругается.
- Сербский текст прячется не только в `prompt` и вариантах. Он есть в `meta` спряжения
  («nemati — так же, + nemam»), в переводах слов `ru` («какой (локатив от koji)»), в
  `instruction`, в пояснениях `note`, в заметке над шагом «Практика» и в блоках кода
  (там набраны параллельные диалоги «сербский — русский»). Всё это идёт через `show()`.
- Каждый новый экран, показывающий сербский текст, обязан пропустить его через
  `show()` и получить тест в режиме кириллицы (образцы: `exercisesScript.test.ts`,
  `ReviewView.test.ts`). Тесты компонентов получают пустой Pinia из
  `web/src/test/setup.ts`.

### «Повторить»

Карточка «Повторить задания» в профиле (`ProgressDashboard.vue`, всегда на месте, одна на всю ширину; не путать с
карточкой «Повторить слова» над ней: это SRS-повторение слов) ведёт на `/repeat`
(`views/RepeatView.vue`; старый `/mistakes` перенаправляет). Все выходы с экрана возвращают в профиль. Спека: `docs/superpowers/specs/2026-10-23-repeat-design.md`.

`GET /api/repeat?audio=off` (`api/repeat.go`) отдаёт серию из 15 уже решавшихся заданий без ответов
(`toExerciseDTO`, как в уроке). Отбор — чистая функция `internal/repeat.Select`: сначала задания, где
последняя попытка неверная (больше всего ошибок первыми), потом «почти» (последняя попытка верная, но
`attempts.typo = 1`; свежие первыми), потом остальные решённые случайно с весом
`уровень (1…6, позиция фазы в course.yaml) × (1 + min(дней с последней попытки, 30) / 10)`; ответы
сегодняшнего дня берутся в последнюю очередь, только если серия не набралась (иначе ученик, который только что
прошёл урок, получал пустое «Повторить» или серию из одной случайной ошибки, и день тратился). Закрытые уровни и задания, которых нет в курсе, пропускаются.

**Один раз в день** (день по `users.timezone`): набор хранится в `repeat_sessions` (`day`,
`exercise_ids`, `after_attempt` = номер последней попытки на старте). Серия «пройдена», когда у каждого
задания есть верная попытка с бо́льшим номером (`RepeatPending`), не по времени: два ответа в одну секунду
остаются по порядку. Начатая серия возвращается до конца (только нерешённые, `session.remaining`),
пустой пул день не тратит. Закончил — сервер отвечает **402 `repeat_limit`** с `next_available`, и
`RepeatView` показывает `RepeatLimitModal` («Можете оформить подписку, чтобы использовать повторения
без ограничений», сцена на всю ширину `assets/repeat-limit-scene.webp` (пиксель-арт 3:2, сейчас 1264×848: грустная ласточка на ветке с «выключенной» табличкой повтора; замена картинки = замена файла, важное держи в центральных 70% по ширине и высоте, окно обрезает до ~1,85:1 и растворяет нижние 12%), кнопка «Повторять без ограничений» всегда активна; аккаунт без тарифов роутер отправит дальше в профиль). Саму кнопку («Повторить задания» в профиле) никогда не блокируем.

**Безлимит** (`Store.HasUnlimitedRepeat`): активный «Год» (`AllAccessUntil`) или оплата рублями «Уровня»
(`HasPaidLevel`, тестовый платёж считается; уровень за зёрнышки не считается). Тогда каждое нажатие
даёт новую серию (`unlimited: true`, кнопка «Ещё серию»), набор не хранится. Строка про безлимитные
повторения стоит в карточках «Год» и «Уровень» на экране тарифов (`TariffsView.vue`); поменяешь условие
безлимита, поменяй и её.

Ответы идут через обычный `check`, который теперь пишет `typo` (`resp.Typo`). Старые попытки до
миграции 031 имеют `typo = 0`: «почти» восстановить нельзя.

### Напоминание про «Повторить» в Telegram

Бот пишет ученику, который ещё занимается, но два дня не открывал «Повторить» (2026-10-30, ветка `feat/repeat-nudge`, не
задеплоено; спека `docs/superpowers/specs/2026-10-30-repeat-nudge-design.md`). Все условия в одной чистой функции
`repeat.NudgeDue`: ученик уже открывал «Повторить» хотя бы раз, прошло 48 часов, он занимался за эти 48 часов, сейчас
10:00–20:00 по его часовому поясу, сообщение одно за затишье (следующее только после того, как он сам откроет «Повторить» и
снова пропадёт), не больше одного учебного сообщения в сутки, категория «учёба» включена и не нажато «Не про повторения».
Правило «одно в сутки» общее для трёх сообщений (`studyMessageGap` в `reminders.go`): «Все слова сделаны», «Давно не
заглядывал» и это; созревшее вторым ждёт следующего обхода после суток. Запись `repeat_nudges` идёт одним SQL-запросом с
проверкой (`RecordRepeatNudge`), поэтому два обхода сразу не дадут дубль. Рассылка выключена, пока не задано `REPEAT_NUDGE=1`
(выкладка её не запускает, пока выключено, не пишется и контрольных строк). Разовое знакомство «Пройденные уроки можно
повторять» всем, кто занимался, но не открывал раздел (`repeat.IntroDue`, `maybeIntroRepeat`): `REPEAT_INTRO=1`, не больше
`repeatIntroPerSweep` за обход ради лимитов Telegram, без контрольной группы. Кнопка каждого из четырёх сообщений ведёт на
`/repeat?n=<токен>`, `api.RepeatClickTracker` пишет `repeat_nudges.clicked_at` (миграция 036).
Вызывается из `RunReminderSweep` (`api/repeat_nudge.go`, `maybeNudgeRepeat`). Половина учеников (`repeat.InControl`) сообщений
не получает, для них пишется строка `repeat_nudges` с `kind = 'control'`, чтобы было с чем сравнить (`Store.RepeatNudgeStats`).
Последнее открытие пишет `GET /api/repeat` всем (`UserStore.NoteRepeatOpened`), потому что у учеников с безлимитом нет строки
в `repeat_sessions`. Три текста по кругу, от лица «мы», одно сербское слово и 1–2 эмодзи (держит `repeat_nudge_test.go`);
меняешь число заданий (`repeat.Size`), меняй и «пятнадцать» в текстах. Кнопки: пресет `InlineButton.RepeatNudgeURL`
(«Повторить» в Mini App и «🔕 Не про повторения», `nudgeoff:repeat`, разбирает `prefPressed`). Выкладка: миграция 035 и
`GRANT SELECT ON repeat_state, repeat_nudges TO ucimo_admin_ro` руками.

### Квест «Подписаться на канал»

Канал — настройка `telegram_channel` (`economy_settings`, правится в админке;
миграция 019 ставит `@ucimosrb` там, где она пустая — пустая настройка прячет
квест). Подписку проверяет сервер через `getChatMember` при каждой загрузке
списка заданий, бот должен быть админом канала. Три пути, кнопка в строке
задания (`QuestsView.vue`) выбирает по полям квеста `url` / `needs_telegram`:

1. Telegram привязан → ссылка на канал, после неё «Проверить подписку»
   (ответ — тост).
2. Уже подписан → квест приходит выполненным, кнопки нет.
3. Telegram не привязан → привязка через бота с намерением `channel`
   (`POST /api/me/telegram/start {"intent":"channel"}`, живёт в `PendingStore`);
   после привязки бот присылает «Подписаться на канал» + «Проверить подписку»
   (`InlineButton.ChannelURL`, в очереди — тип `channel_check`), а нажатие
   «Проверить» разбирает вебхук (`callback_query`, `channelCheckPressed`):
   notice поверх чата + сообщение с итогом. Тексты — `channel_prompt`,
   `channel_ok`, `channel_not_yet` (в `bot_messages` для старых баз их нет,
   работают дефолты из `telegram.DefaultMessages`).

Вебхук работает только на публичном https, поэтому путь 3 локально целиком не
проверить: покрыт тестами (`telegram_bot_test.go`) и проверяется на проде.

### Сообщения бота и отписка

Бот пишет только тем, у кого привязан Telegram, и то, что человек не отключил.
Таблица `bot_prefs` (миграция 023) держит три переключателя: `learning` (напоминания об
учёбе, включено), `billing` (про тариф, включено), `news` (новости и предложения,
**выключено**: это реклама, нужен явный «да»). Нет строки — значит значения по умолчанию.
Служебные сообщения (вход, оплата получена, доступ открыт) в таблицу не входят и приходят
всегда: это ответ на действие человека.

Отключить можно в трёх местах, всё пишет в одну таблицу: профиль → Настройки (`GET/PUT
/api/me/bot-prefs`, `BotPrefsSection.vue`), кнопка «🔕 Не напоминать» под напоминанием
(callback `prefoff:<категория>`), команды `/stop` и `/settings` (callback `pref:<категория>:<0|1>`,
клавиатура перерисовывается через `editMessageReplyMarkup`). Все три разбирает
`api/bot_prefs.go`, кнопки — `telegram/prefs.go`.

**Новое несервисное сообщение бота обязано:** проверить `Store.BotPrefs` своей категории
перед постановкой в очередь (как `RunReminderSweep`) и нести кнопку отписки
(`InlineButton.PrefOff`). Кнопка хранится в `bot_outbox` одной строкой
(`outbox.ButtonRow`/`buttonFromRow`, тест на круг туда-обратно). Что ещё бот мог бы
писать и с какими правилами частоты — `docs/TELEGRAM_MESSAGES.md`.

### Тарифы и оплата рублями

Подробно — `docs/superpowers/specs/2026-10-14-tariffs-design.md`. Коротко: «Уровень»
(один уровень на выбор человека, навсегда, 199 ₽ в первый раз, потом 299 ₽; цены в таблице `tariffs`, сменил миграцией 027, и они же названы в оферте п. 4.1: менять вместе) и «Год» (все
уровни на 365 дней, 1000 ₽), оплата через Т-Кассу (Т-Банк), разовая, без автопродления. ЮKassa убрана целиком 2026-10-26: пакета, вебхука и переменных `YOOKASSA_*` больше нет, старые платежи `provider = 'yookassa'` лежат в таблице и никем не закрываются.

**Закрыто для всех, кроме `TARIFFS_EMAILS` и `TBANK_EMAILS` (два списка с одним действием, оба платят
через Т-Кассу)** — подтверждённые почты через запятую. **С `TARIFFS_FOR_ALL=1` (включено 2026-10-17)
открыто всем, у кого подтверждённая почта, и они тоже платят через Т-Кассу. Аккаунт без
почты (только Telegram, то есть почти всякий пользователь Mini App) тоже видит тарифы, но
почту или телефон для чека вводит сам в окне `ReceiptContactModal`, которое открывается нажатием любой кнопки оплаты на
экране тарифов (аккаунту с почтой окно не показывается, кроме dev-сборки `make dev`: там оно открывается и админу с почтой,
чтобы его можно было посмотреть, введённое тогда не отправляется, а `?receipt=0` на странице это отключает; в боевой сборке
такой ветки нет; введённое запоминается на устройстве и подставляется в поле,
`POST /api/me/orders {tariff, contact}`,
ошибка `receipt_contact_invalid`; банку уходит `Receipt.Email` или `Receipt.Phone` в виде
`+79031234567`, российские записи 8…/7…/10 цифр приводятся к `+7…`, международные только с
плюсом; контакт лежит в `payments.receipt_contact`). Аккаунт с введённой,
но неподтверждённой почтой по-прежнему ничего не видит.** Сервер
отдаёт `features.tariffs` в аккаунте и отвечает 404 на `/api/me/tariffs`, `/api/me/orders*`
всем остальным; фронт прячет страницу, баннер, кнопку оплаты в окне «не хватает зёрнышек» и
карточку в профиле (`stores/tariffs.ts` → `enabled`). Новая точка входа в оплату обязана
проверять `tariffs.enabled`.

**Выбор уровня после оплаты** (2026-10-26, спека `docs/superpowers/specs/2026-10-26-level-choice-design.md`):
платёж за «Уровень» выдаёт **право на один уровень**, а какой, человек решает сам. Раньше заказ в момент создания
записывал в `payments.granted_phase` «следующий закрытый» уровень, теперь `granted_phase` у такого заказа пустой, и
`CompletePayment` уровня не открывает (бонус зёрнышек, безлимит повторений и месячный лимит работают сразу). Право =
успешный платёж `level` с пустым `granted_phase` (миграции нет). `Store.ClaimLevel` тратит его один раз (повтор того же
уровня ок, другой `ErrCreditSpent`), `Store.UnclaimedLevelPayments` отдаёт неистраченные. API: `GET /api/me/tariffs`
в `level` отдаёт `choices` (закрытые и в продаже уровни по порядку курса: `id`, `title`, `lessons`, `after`) и `credits`
(номера неистраченных заказов), `level.next` оставлен (первый вариант); `POST /api/me/orders/{id}/level {phase}` тратит
право (404 чужой заказ, 409 `not_claimable`, 400 `bad_phase`, 409 `already_chosen`); `orderDTO.choose` у оплаченного
заказа без уровня. Пока право не потрачено, новый уровень купить нельзя (409 `level_pending_choice`); год открывает всё,
вариантов тогда нет. Сайт: `LevelChoiceModal` (монтируется в `AppNav`, состояние `lib/levelChoiceModal.ts`): картинка
с ласточкой, карточки неоткрытых уровней (номер, название, темы из магазина, число уроков; первый «Следующий по порядку»,
у остальных «Лучше после «…»»), выбор и отдельная кнопка «Открыть «…»» (два шага, выбор не отменить), итог с «Hvala lepo»
и сердечком. Закрыли, не выбрав: право не пропадает, `LevelCreditNotice` («Оплаченный уровень ждёт вас») вверху профиля
и страницы тарифов, окно снова открывается при заходе на страницу тарифов. Админка показывает такой платёж как
«Уровень (ждёт выбора)». Окно «не хватает зёрнышек» (`UnlockLevelModal`, `offerForPhase` в `lib/tariffs.ts`) предлагает «Уровень» (первый тариф) для
любого закрытого уровня в продаже, не только для следующего (человек выберет после оплаты). **Окно намеренно короткое**
(владелец 2026-10-26: «много всего написано, надо поменьше и чтобы хотелось взять»; тест `stays short` держит до 200 знаков):
картинка с ласточкой и зёрнышком (`assets/tariffs-promo-scene.webp`, в обоих состояниях окна), название уровня и цена в зёрнышках,
«Не хватает 130 зёрнышек», крючок «Откройте сразу — и 1 000 зёрнышек в подарок», золотая кнопка «Хочу уровень — 199 ₽» с
зачёркнутой обычной ценой внутри (скидка первой покупки без отдельной строки), мелко «Навсегда, без подписки. Hvala lepo ♥» и
тихая ссылка «Заработать зёрнышки» вместо второй кнопки. Не возвращать: пояснение про выбор уровня после оплаты, отдельные строки
про скидку и про то, где брать зёрнышки, «Позже» (закрывает крестик). Золотая кнопка (`.btn-seed` в `style.css`, та же, что
«Забрать» награду на экране заданий) стоит на всех предложениях платить; тон баннера и канала («вы»), остальные состояния окна тоже
на «вы». Особые случаи: пока право не потрачено, вместо покупки золотая «Выбрать уровень» (`kind: 'credit'`, открывает
`LevelChoiceModal`); пока держит месячный лимит (оферта п. 2.2), «Уровень» всё равно первым, но кнопка неактивна, а над ней строка
с датой («Уровень за рубли можно взять с 20 ноября»), без крючка. **Про год в этом окне нет ничего** (владелец: «убери вообще про
год»); год продаётся только на экране тарифов. Слов «уровни открываются по порядку» нет. в прод-Postgres, иначе страница ответит 503.

аккаунта, их зёрнышки и открытые ими уровни, остальное не трогает (если бонус уже сняли вручную и баланс ушёл бы в минус, скрипт
выравнивает его до нуля корректировкой), `make dev` можно не останавливать; для второй покупки
подряд ещё нужен `TARIFF_LEVEL_COOLDOWN_DAYS=0` (иначе один уровень в месяц).

Один «Уровень» в месяц: после оплаченного уровня следующий за рубли нельзя купить
`TARIFF_LEVEL_COOLDOWN_DAYS` дней (по умолчанию 30, 0 = выкл.): `POST /api/me/orders`
отвечает 409 `level_cooldown`, `GET /api/me/tariffs` отдаёт `level.available_from`.
Считается от последнего оплаченного уровня (`Store.LastLevelPaymentAt`, тестовые платежи
тоже), год и уровни за зёрнышки не ограничены. 30 дней записаны и в публичной оферте
(п. 2.2): менять вместе. Скидку первой покупки («−17%») и выгоду года экран считает из тех же цен, что и кнопки
(`lib/tariffs.ts`: `discountPercent`, `monthlyYearCost`, `yearSaving`), и ничего не заявляет, если выгоды нет. Выгода года
считается против «уровня каждый месяц, двенадцать месяцев»: первый по цене человека, одиннадцать по обычной (199 + 11 × 299 =
3 488 ₽, `stores/tariffs.ts` `monthlyCost`). Это решение владельца (2026-10-28): я пробовал считать по числу ещё закрытых
платных уровней (сейчас их пять, получалось 1 395 ₽ и «Выгода 28%», а у человека с тремя закрытыми выгоды не было), владелец
назвал эти числа неправильными и велел вернуть двенадцать месяцев; год открывает и уровни, которые ещё выйдут. Не менять
обратно без него.

`CompletePayment` начисляет её в той же транзакции, что и доступ, одной записью `topup`

### Карта курса: прокрутка к последнему уроку

При открытии `CourseView` экран один раз прокручивается к уроку, который учили последним
(`lib/lastStudied.ts`): последний начатый, а если начатых нет — последний пройденный. Если
уровень с этим уроком свёрнут, прокрутка идёт к заголовку уровня (`data-phase`), карточка
урока (`data-lesson`) в DOM не существует. Курс в сторе кэшируется, поэтому перед прокруткой
идёт тихое `course.refresh()` (без состояния загрузки), иначе статусы были бы устаревшими.

### Звук и вибрация

Свои звуки приложения (не кнопки-динамики, которые нажимает сам ученик): аккорд и
вибрация в конце урока, озвучка верного предложения после ответа. Всё в
`web/src/lib/sound.ts`; настройки «Звук» и «Вибрация» (`SoundSettings.vue`, в профиле →
Настройки) хранятся в `localStorage` устройства (`srpski.sound`, `srpski.haptics`), не в
аккаунте, по умолчанию включены. «Звук» гасит и аккорд, и озвучку предложений; «Вибрация»
видна только внутри Mini App.
- Экран итогов (`LessonSummary.vue`) зовёт `celebrate()` при появлении: аккорд (Web Audio,
  файлов нет) + `Telegram.WebApp.HapticFeedback.notificationOccurred('success')`. Экран
  показывается только при первом завершении урока, при повторном просмотре звука нет.
- Озвучка: `<PhraseSpeak autoplay>` в блоках результата `TextAnswer`, `ChoiceAnswer`,
  `WordBankAnswer` читает тот же клип, что кнопка динамика под вердиктом: верное
  предложение, при ошибке тоже верное, а не выбранное. Только в момент появления вердикта
  (в уроке все упражнения шага лежат в DOM, запоздавший индекс клипов не должен
  озвучивать их разом); ветки «ранее отвечено» не играют. `conjugate`, `match` и диктант
  без автоозвучки: у них нет одного предложения (у диктанта оно только что прозвучало).
- Телефоны разрешают звук только после касания, а наш стартует после ответа сервера.
  Поэтому `installAudioUnlock()` (в `main.ts`) на первом касании будит `AudioContext` и
  один общий `<audio>`; предложения играют через него, а не через новый `Audio()` на каждое.
- Признак Mini App: `inMiniApp()` = `isTelegram() && initData()`. `telegram-web-app.js`
  грузится в любом браузере, поэтому одного `isTelegram()` мало. Вибрация есть с Mini App
  6.1, старый клиент пропускается через `isVersionAtLeast`.
- Не проверено вживую: слышимость и вибрация на настоящем телефоне, поведение
  автовоспроизведения на iOS (в браузере проверены вызовы, а не звук).

## SRS-очередь повторения (`/api/review/queue`, `ReviewView.vue`)

Карточки — слова (`vocab:<id>`) и ложные друзья (`ff:<id>`), SM-2
(`internal/srs`). Новые слова не выдаются пачкой — гейтятся по одному в

(4 варианта, `buildOptions`), а не открытый ответ.

## Стиль

- Go: как в соседних файлах, короткие доки-комментарии на экспортных
  символах, ошибки оборачивай (`fmt.Errorf("...: %w")`).
- Комментарии в коде — по-английски, тексты для пользователя и контент —
  по-русски/сербски.
- Тесты рядом с кодом, table-driven где уместно.
